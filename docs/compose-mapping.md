# docker-compose.yml (dev) -> packaging/docker-compose.release.yml (release)

Every service, volume and capability of the development compose file exists in the
release file. What differs, and why:

| Item | Dev (`docker-compose.yml`) | Release | Reason |
|---|---|---|---|
| `db` image | `postgres:16-alpine` built-in tag | same image, pinned by digest via `release.env` | immutability |
| `db` published port | `127.0.0.1:5433:5432` | none | no host-side tooling needed; smaller attack surface |
| `redis` | `redis:7.4-alpine`, `--appendonly yes` | same | M5 offset persistence unchanged |
| `helper` build | `build: ./helper` | `image: HELPER_IMAGE` (built from `packaging/docker/Dockerfile.helper` = `helper/Dockerfile` minus tests) | no source at deploy time |
| `helper` caps | `cap_drop: ALL`, add `NET_ADMIN NET_RAW SYS_NICE CHOWN` | identical | privilege model preserved, never `privileged: true` |
| `helper` network | `network_mode: host` | identical | needed for discovery and capture |
| `helper` volumes | socket, suricata rules, staging, logs, run, `suricata.yaml` | identical; `suricata.yaml` from `/opt/sentinelcore/suricata/` | same files, installed by the installer |
| `helper` healthcheck | none | socket exists | lets `backend` wait for the helper |
| `backend` build | `build: ./backend`, bind mount `./backend:/app`, `uvicorn --reload` | `image: BACKEND_IMAGE` (`packaging/docker/Dockerfile.backend`: no tests, no `--reload`), no bind mount | production image |
| `backend` env | `.env` + `DATABASE_URL`, `REDIS_URL`, `HELPER_SOCKET_PATH` | same, plus `ENVIRONMENT=production` | hides `/api/docs`, marks cookies Secure |
| `backend` volumes | socket, staging, logs (ro), reports, pcap | identical | M4/M9/M11 unchanged |
| `backend` hardening | `cap_drop: ALL`, `no-new-privileges` | identical + healthcheck on `/api/health` | |
| `worker` | same image, `python -m app.pipeline.worker`, `RUN_MIGRATIONS=false` | identical | M5/M10/M11/M12 background loops unchanged |
| `frontend` | Vite dev server, source bind-mounted | static build served by unprivileged nginx on 8080 (`frontend/Dockerfile.prod`) | no dev server in production |
| `nginx` | HTTP only, port 80, proxies Vite HMR | HTTP->HTTPS redirect, TLS 1.2+, security headers, proxies `/api/` to backend and `/` to frontend | spec |
| `nginx` ports | `80:80` | `LISTEN_ADDRESS:HTTP_PORT:80`, `LISTEN_ADDRESS:HTTPS_PORT:443` | wizard-chosen access |
| volumes | postgres_data, redis_data, helper_socket, rule_staging, suricata_rules/logs/run, report_storage, pcap_storage | identical | nothing dropped |
| network | `sentinelcore-network` bridge | identical | |
| env file | `.env` in the repo | `/etc/sentinelcore/sentinelcore.env` (0600) generated by the wizard | secrets never in the package |

Variables the wizard collects map to the **existing** application variables only:
`CAPTURE_INTERFACE`, `MONITORED_NETWORK`, `PROTECTED_IPS`, `EVENT_RETENTION_DAYS`,
`SEED_ADMIN_USERNAME/PASSWORD/EMAIL`, `POSTGRES_*` and `SECRET_KEY` (generated).
Deployment-only variables (`LISTEN_ADDRESS`, `HTTP_PORT`, `HTTPS_PORT`, `PUBLIC_HTTPS_SUFFIX`,
`HSTS_MAX_AGE`) are consumed by the compose file and nginx, not by the application.

Existing application files that had to change for the release path: **none**. Production
images are built from new Dockerfiles under `packaging/docker/` and `frontend/Dockerfile.prod`
using the unchanged application source.
